# نسخه اندروید اولیه - رصد نیروهای پروژه

## باز کردن پروژه
پوشه را از حالت فشرده خارج کنید و از Android Studio گزینه Open را روی پوشه اصلی بزنید. Gradle Sync را انجام دهید.

## اتصال به سرور
1. ابتدا backend بسته MVP قبلی را اجرا کنید.
2. در گوشی، آدرس IP قابل دسترس سرور را وارد کنید؛ `10.0.2.2` فقط برای شبیه‌ساز اندروید است.
3. از API یا پنل، نیرو بسازید و شناسه عددی او را وارد کنید.
4. شروع شیفت را بزنید و پس از پایان، «پایان شیفت» را انتخاب کنید.

## ساخت APK آزمایشی
از Android Studio: Build > Build Bundle(s) / APK(s) > Build APK(s).
خروجی معمولاً در `app/build/outputs/apk/debug/app-debug.apk` قرار می‌گیرد.

## محدودیت‌های مهم این نمونه
- این نسخه برای تست فنی اولیه است، نه بهره‌برداری سازمانی.
- احراز هویت امن، توکن اختصاصی، Room برای صف آفلاین پایدار، صفحه تاریخچه و مدیریت خطا باید پیش از استقرار ۴۰ نفر تکمیل شوند.
- در حال حاضر اگر اپ/سرویس در حین شیفت متوقف شود یا گوشی خاموش شود، پیوستگی مسیر تضمین نیست.
- شروع شیفت از سرور و پایان شیفت هنگام توقف سرویس انجام می‌شود؛ توقف اجباری سیستم‌عامل می‌تواند ثبت پایان را مختل کند. در محصول نهایی باید دکمه پایان با API مستقل و تأیید سرور پیاده شود.
- برچسب پیاده/خودرو در این نسخه هنوز صرفاً با سرعت قابل محاسبه است و تشخیص قطعی نیست.
- مجوزهای موقعیت و اعلان باید با اطلاع‌رسانی روشن به نیرو دریافت شوند. رصد خارج از شیفت انجام نشود.
- برای انتشار عمومی، HTTPS، امضای APK، محدودسازی دسترسی و بررسی مقررات حریم خصوصی لازم است.
